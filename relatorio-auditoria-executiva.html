Sumário Executivo

O TheraFlow é uma plataforma SPA de gestão clínica para psicólogos brasileiros com portal dedicado ao paciente. O produto demonstra solidez técnica e cuidado com a experiência clínica, mas enfrenta riscos críticos de arquitetura (localStorage como base de dados primária), ausência de modelo de monetização ativo, lacunas de conformidade com a LGPD e zero infraestrutura de crescimento. Esta auditoria mapeia os pontos fortes, riscos e o roadmap recomendado para as próximas três fases de evolução.

Perspectiva 01 — CEO

Estratégia & Posicionamento

⚠ Potencial alto — execução de negócio ausente
✅ Ponto Forte
Nicho claro e bem delimitado: psicólogos brasileiros em consultório particular, um segmento de ~170 mil profissionais com baixíssima digitalização.
✅ Ponto Forte
Produto dual (terapeuta + paciente) cria lock-in natural e diferencia do concorrente genérico. Nenhum player no BR combina gestão + portal do paciente com gamificação.
🔴 Risco Crítico
Empresa sem modelo de receita ativo. Sem Stripe, sem plano pago, sem freemium estruturado — o produto é gratuito por padrão, o que impede valuation e captação.
⚠ Atenção
Posicionamento implícito ("feito por psicólogos") nunca comunicado explicitamente. Narrativa de marca não existe — há produto, não há história.
Recomendação CEO O risco existencial não é técnico — é ausência de go-to-market. O produto precisa de landing page, pricing page e pelo menos um plano pago nos próximos 60 dias antes de qualquer nova feature.

Perspectiva 03 — CTO

Arquitetura & Tecnologia

🔴 Risco técnico crítico — ação imediata necessária
⚠ Risco Crítico — localStorage como Banco de Dados A arquitetura atual usa localStorage (tf_patients, tf_appointments, tf_charges) como fonte primária de dados do terapeuta. Isso significa: dados perdidos ao limpar cache do navegador, dados não acessíveis em outros dispositivos, dados não compartilháveis entre dispositivos de uma mesma clínica, e zero backup automático. Este é o risco existencial #1 do produto.
✅ Stack Moderna
Vercel (serverless), Supabase Auth + PostgreSQL, Claude (Anthropic) para IA, PWA com manifest. Stack serverless reduz custo operacional para quase zero nos primeiros anos.
✅ Segurança de Chaves
Chaves sensíveis (SUPABASE_SERVICE_ROLE_KEY, ANTHROPIC_API_KEY) isoladas em serverless functions no Vercel. Nunca expostas no cliente.
🔴 localStorage Frágil
Dados do terapeuta (pacientes, agenda, cobranças) vivem apenas no navegador local. Um clear de cache destrói todos os dados. Não há sync nem backup.
🔴 SPA Monolítica
~14.500 linhas em um único arquivo HTML. Impossível fazer code-splitting, lazy loading, testes unitários. Cada deploy é um big bang.
⚠ Service Worker Ausente
O app é instalável como PWA mas não tem service worker. Sem cache offline, sem estratégia de atualização silenciosa, notificações dependem do navegador aberto.
⚠ Sem Testes
Zero testes automatizados (unit, integration, e2e). Qualquer refactoring é risco alto. Bugs silenciosos são impossíveis de detectar sistematicamente.

Dívida Técnica — Priorizada

  • P1
    Migrar dados do terapeuta para Supabase. Criar tabelas patients, appointments, charges com RLS por therapist_id. localStorage vira cache local, Supabase vira fonte da verdade.
  • P1
    Implementar service worker. Cache offline das páginas principais, sync em background quando reconectar, push notifications independentes do app aberto.
  • P2
    Modularizar o HTML em componentes. Migração gradual para arquivos JS separados (ex: portal-patient.js, dashboard.js). Não precisa ser React — basta separar responsabilidades.
  • P2
    Adicionar testes de integração para fluxos críticos. Login, salvar paciente, registrar cobrança, portal do paciente. Playwright ou Cypress com 20 testes cobre 80% dos riscos.
  • P3
    Configurar Sentry ou similar. Monitoramento de erros em produção. Atualmente, bugs silenciosos de usuários reais são invisíveis.

Perspectiva 04 — COO

Operações & Suporte

⚠ Infra OK — processos ausentes
✅ Deploy Simples
Vercel automatiza deploy a cada push no master. Zero configuração de servidor. Downtime praticamente nulo com edge network global.
✅ Onboarding Funcional
Fluxo de cadastro do terapeuta implementado (email, senha, perfil, abordagem). Paciente recebe acesso via portal com senha gerada pelo terapeuta.
🔴 Sem Canal de Suporte
Nenhum canal de suporte ao usuário (chat, email, base de conhecimento). Um terapeuta com problema não tem para onde ir — churna silenciosamente.
⚠ Sem Métricas de Uso
Zero analytics (Google Analytics, Mixpanel, Posthog). Impossível saber quantos usuários ativos, quais features usam, onde abandonam o onboarding.
Ação Imediata Recomendada Instalar Posthog (gratuito, self-hosted opcional, LGPD-friendly) para tracking de eventos. Com 5 eventos instrumentados (login, salvar paciente, abrir portal, registrar humor, emitir cobrança) já é possível tomar decisões de produto baseadas em dados.

Perspectiva 05 — CFO

Financeiro & Monetização

🔴 Sem receita — risco de sustentabilidade
Estado Atual O produto não gera nenhuma receita. Não há Stripe conectado, não há plano pago, não há cobrança de nenhuma espécie. Custo mensal estimado: ~R$ 0 (Vercel free tier + Supabase free tier). Isso é sustentável para MVP mas não para escala.
ℹ Modelo Sugerido — Freemium
Gratuito: 1 terapeuta, até 10 pacientes, sem IA, sem portal do paciente.
Profissional (R$ 89/mês): ilimitado, IA clínica, portal completo, notificações.
Clínica (R$ 249/mês): múltiplos terapeutas, relatórios gerenciais.
ℹ Projeção Conservadora
500 usuários pagantes ao preço de R$ 89/mês = R$ 44.500 MRR (R$ 534k ARR). Meta realista em 18 meses com go-to-market estruturado. CAC estimado: R$ 60–120 (SEO + referral).
⚠ Custo de Escala
Claude API: ~$0,001/chamada. Com 10k chamadas/mês = $10 (R$ 50).Supabase Pro: $25/mês. Custo total de infra a 1.000 usuários: ~R$ 400/mês. Margens excelentes.
⚠ Churn Risco
localStorage como banco de dados pode gerar churn por perda de dados — o pior tipo de churn (involuntário e com NPS destruído). Resolver antes de monetizar.

Plano de Monetização Recomendado

  • P1
    Integrar Stripe Checkout. Criar serverless function /api/create-checkout. Plano anual com 20% de desconto como âncora de conversão.
  • P1
    Feature flag por plano. Bloquear IA e portal do paciente no free tier via verificação de account.plan no Supabase. Urgência para upgrade natural.
  • P2
    Trial de 14 dias. Todo cadastro inicia como Profissional por 14 dias. Coleta cartão antecipado via Stripe com cobrança diferida (trial sem cobrança imediata).
  • P3
    Nota fiscal automática. Integração com Nuvem Fiscal ou Omie para emitir NF-e de serviço automaticamente ao receber pagamento — diferencial para PJ psicólogos.

Perspectiva 07 — Head of Growth

Aquisição, Retenção & Viralidade

⚠ Produto retentivo — acquisition zero
✅ Retenção Natural Alta
Psicólogos que cadastram 10+ pacientes dificilmente migram — o custo de reentrada de dados é altíssimo. Lock-in por dados é a melhor retenção possível.
✅ Viralidade Embutida
Cada terapeuta que usa o portal convida seus pacientes. Se 1 terapeuta tem 20 pacientes, cada conversão traz 20 usuários adicionais — loop viral orgânico.
🔴 Sem Funil de Aquisição
Não há tráfego orgânico, pago, social ou referral estruturado. Todo usuário atual chegou por indicação direta ou por coincidência. Escalabilidade de aquisição: zero.
⚠ Sem Loop de Referral
Psicólogos adoram recomendar ferramentas para colegas. Um programa "indique e ganhe 1 mês grátis" poderia gerar CAC negativo. Não existe.

Perspectiva 08 — Legal & Segurança

LGPD, CFP & Segurança da Informação

🔴 Exposição regulatória alta
✅ Segurança de Credenciais
Chaves de API (Supabase service role, Gemini) nunca expostas no cliente. Isoladas em serverless functions no Vercel. CORS restrito a origins autorizadas.
✅ Auth Robusto
Supabase Auth com JWT, dois contextos separados (terapeuta/paciente), RLS no banco — usuários só acessam seus próprios dados.
🔴 Sem Política de Privacidade
A LGPD exige política de privacidade pública explicitando: dados coletados, finalidade, base legal, direitos do titular, DPO. Ausência pode gerar multa de até R$ 50M.
🔴 Dados Sensíveis sem DPA
Prontuários psicológicos são dados sensíveis (art. 11 LGPD). Exigem base legal específica (consentimento ou tratamento de saúde) e Data Processing Agreement com Supabase/Vercel.
⚠ Sem Termo de Uso
Não há termos de uso com responsabilidades, limitação de responsabilidade, SLA, ou cláusula de rescisão. Risco jurídico na relação com terapeutas.
⚠ Resolução CFP nº 11/2018
Regulamenta atendimento psicológico mediado por tecnologia. O TheraFlow não documenta conformidade com normas de sigilo profissional e segurança de dados clínicos.

Checklist de Conformidade LGPD

  • P1
    Redigir e publicar Política de Privacidade. Incluir: dados coletados, finalidade, base legal (art. 7 e 11), prazo de retenção, direitos do titular, contato do DPO.
  • P1
    Termo de Consentimento no cadastro de pacientes. O terapeuta deve registrar consentimento do paciente para uso de dados em plataforma digital de saúde.
  • P1
    Assinar DPA com Supabase e Vercel. Ambos oferecem Data Processing Agreements — necessário para dados de saúde em conformidade com LGPD.
  • P2
    Implementar "Direito ao Esquecimento". Função de exportação + exclusão completa de dados de um paciente, acionável pelo terapeuta ou pelo próprio paciente.
  • P2
    Redigir Termos de Uso. Responsabilidades do terapeuta como controlador de dados, limitação de responsabilidade do TheraFlow como operador.
  • P3
    Criptografia em repouso para prontuários. Supabase já criptografa o disco — documentar e comunicar esta conformidade aos terapeutas.

Conclusão da Auditoria O TheraFlow tem o produto mais completo do segmento de gestão clínica para psicólogos no Brasil. O diferencial do portal do paciente com gamificação é genuinamente único. A prioridade imediata é: (1) resolver o risco de perda de dados via localStorage, (2) publicar documentação LGPD, (3) ativar monetização. Com essas três ações, o produto está apto a crescer com segurança.
